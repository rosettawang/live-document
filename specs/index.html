Three fixes the test pass produced — all shipped Aug 5, 2026

  1. Rotating DOC_PASSCODE silently bricks every open tab. Cookies are signed with it, so a rotation invalidates them all — and the page kept looking alive: the socket retried forever against gate HTML and fetches tried to JSON.parse it. API and socket paths now return 401, and the client turns three straight failures into a visible "Signed out — sign in again". This is not a rare path; the secret was rotated twice on the first day.
  2. Popovers used page coordinates. The hover strip and comment box were position:absolute at scrollY + rect.top, which lets them extend the document. Now position:fixed in viewport coordinates, clamped on screen.
  3. Assets were cacheable forever. A fixed app.js deployed to Cloudflare while a browser kept running the old one. The shell now links app.js?v=<hash>, so a reload always gets the current client — which matters for a page four people leave open for eleven days and will never think to hard-refresh.

How this works

Conventionsborrowed wholesale from whrfund-website

Same format as whrfund-website/specs/: HTML, read in a browser, sharing one spec.css. Each spec declares <meta name="spec-status"> of open, blocked, done or canonical, plus spec-priority (lower sorts sooner) with a one-line spec-priority-why, spec-touches, and one spec-decision per choice that is Rosetta's.

Two things from that repo are deliberately not here. There is no specs:prune / specs:plan script, so the order above and the lists are hand-derived and dated rather than generated — if those scripts get ported, they write between the GENERATED:EXECUTION-ORDER markers, which are already in place. And there is no RUN-LOG.html, because this was one sitting rather than a run.

The writing standard from that repo's CLAUDE.md applies to this file: never state machine-checkable state from memory, date every status claim, separate verified from assumed. Every count and status above was derived by a command on Aug 5, 2026.

The originals are no longer the source of truth

After the first seed, iceland-eclipse-2026.html and packing/packing-list.html are historical. Editing them changes nothing. build:shell regenerates the seed files, but the Durable Objects only import a seed into an empty document — so a rebuild cannot overwrite eleven days of real planning, and equally cannot be used to push a change into a live document.
